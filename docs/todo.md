# План работ (этапы)

Каждый этап — самостоятельный инкремент с проверяемым результатом.
Любой агент может продолжить с места остановки: состояние репозитория после
каждого этапа собирается (`go build ./...`), тесты этапа зелёные.
Отмечать выполненное: `[x]`.

## Этап 0. Анализ и подготовка репозитория — ВЫПОЛНЕН

- [x] Анализ схемы dict.xml, сбор метрик (см. docs/requirements.md).
- [x] Проектирование структуры хранения (docs/implementation.md).
- [x] Фиксация требований FT1–FT9 (docs/requirements.md).
- [x] Удаление устаревшего кода из internal/ и pkg/ (объектная модель индекса,
  binutils-сериализация, generic XML-парсер). Сохранены: pkg/common,
  pkg/opencorpora (только загрузка/распаковка), cmd/opencorpora_update
  (загрузка+распаковка). Проверка: `go build ./...`, `go vet ./...`,
  `go test ./...` — зелёные; `go mod tidy && go mod vendor` без лишних зависимостей.

## Этап 1. Примитивы формата (internal/format) — ВЫПОЛНЕН

Инкремент: пакет кодирования и секционного контейнера.
- [x] varint/delta кодеки ([]uint32, []uint64) — encode/decode roundtrip.
- [x] Заголовок: magic "GMRF", version, xxh3-чексумма; каталог секций
  (имя, offset, size); writer (секции дописываются, каталог в конце)
  и reader (проверки magic/version/чексуммы, доступ к секции по имени).
Проверка (выполнена):
- unit-тесты roundtrip varint/delta на краевых случаях (0, 1, max u32/u64,
  монотонные/немонотонные последовательности) — `TestAppendDelta*Roundtrip`;
- unit-тесты writer→reader: несколько секций (в т.ч. пустых, streaming),
  чтение по имени, ошибки при битой чексумме/магии/версии/обрезке;
- `go build ./...`, `go vet ./...`, `go test ./internal/format -race` — зелёные.
Ручная проверка: hexdump тестового файла — magic "GMRF", version=1,
indexOffset=0x1C, каталог из 2 секций, trailer xxh3 — читаемы и корректны.

## Этап 2. Интернирование строк (internal/intern, internal/stringsx)

Инкремент: арена строк + таблица интернирования без аллокаций на токен.
- [ ] `stringsx.Arena`: append байт, границы по uint32-оффсетам, Get(i) []byte.
- [ ] `intern.Table`: хеш []byte → id, open addressing, pre-sized, rehash;
  метод Intern(b []byte) (id uint32, existed bool), Get(id) []byte.
Проверка:
- unit-тесты Arena/Intern: дубликаты дают один id; уникальные — новые;
  корректность Get после роста таблицы (rehash);
- benchmark Intern на 1M строк: allocs/op ≈ 0 на повторных вставках;
- `go test ./internal/intern ./internal/stringsx -bench .`

## Этап 3. Сканер dict.xml (internal/xmlscan)

Инкремент: потоковый байтовый сканер фиксированной схемы.
- [ ] Сканер над io.Reader: события OnGrammeme(parent,name), OnLemma(id,text),
      OnForm(text), OnGrammemeRef(v); атрибуты как срезы внутреннего буфера.
- [ ] Обработка границ буфера (перенос незавершённых токенов).
Проверка:
- unit-тесты на мини-фикстурах (строки XML): порядок событий, значения атрибутов;
- unit-тест на обрезку буфера (маленький размер буфера = 64 байта);
- интеграционный smoke: первые 10k лемм реального dict.xml парсятся без ошибок
  (`go test -tags integration` или ручной запуск утилиты);
- сравнение числа событий с эталоном: 391 842 леммы / 5 533 109 строк на полном файле.

## Этап 4. Builder и CSR-структуры (internal/build)

Инкремент: программное наполнение словаря (FT8) + структуры памяти.
- [ ] Builder: AddGrammeme/AddLemma/AddForm, справочники анкодов, CSR-массивы
  лемм/строк, trie (временный, узлы-структуры) → компиляция в CSR
  (stateOff/transitions/finals), постинг-листы с дедупликацией, exact-hash.
- [ ] Метод Build() → иммутабельный снимок (значения, не указатели).
Проверка:
- unit-тесты Builder: маленький словарь (5–10 лемм) вручную; проверка
  lookup по каждому слову, дубликаты форм, одинаковые тексты у разных лемм;
- property-тест: N случайных слов → все найдены; отсутствующие — не найдены;
- `go test ./internal/build -race`.

## Этап 5. Компилятор и загрузчик файла

Инкремент: SaveTo/Open через формат этапа 1 (FT3, FT4).
- [ ] Сериализация снимка в секции: delta/varint для оффсетов и постингов.
- [ ] mmap-ридер (internal/mmapx): Open(path) → Dictionary-снимок.
Проверка:
- roundtrip-тест: Build → SaveTo → Open → равенство выборок по контрольному
  набору слов (golden-набор ~100 слов с ожидаемыми грамматиками);
- тест битого файла: усечение, порча чексуммы → осмысленные ошибки;
- замер размера: словарь из полного dict.xml укладывается в ориентиры FT4
  (логируется в тесте, жёстких ассертов нет до стабилизации).

## Этап 8. Поиск лемм FT5

Инкремент: Lemmas(word) → начальная форма + разборы.

## Этап 9. Нечёткий поиск FT6

Инкремент: Fuzzy(word, k).
- [ ] DFA Левенштейна (без транспозиций) поверх CSR-trie; отсечение по k;
  группировка результатов по дистанции.
Проверка:

- порог k=0 вырождается в точный поиск;
- benchmark: k=2 на полном словаре < 1 c (логируется).
