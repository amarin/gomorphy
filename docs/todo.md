# План работ (этапы)

Каждый этап — самостоятельный инкремент с проверяемым результатом.
Любой агент может продолжить с места остановки: состояние репозитория после
каждого этапа собирается (`go build ./...`), тесты этапа зелёные.
Отмечать выполненное: `[x]`.

## Этап 0. Анализ и подготовка репозитория — ВЫПОЛНЕН

- [x] Анализ схемы dict.xml, сбор метрик (см. docs/requirements.md).
- [x] Проектирование структуры хранения (docs/implementation.md).
- [x] Фиксация требований FT1–FT9 (docs/requirements.md).
- [x] Удаление устаревшего кода из internal/ и pkg/ (объектная модель индекса,
  binutils-сериализация, generic XML-парсер). Сохранены: pkg/common,
  pkg/opencorpora (только загрузка/распаковка), cmd/opencorpora_update
  (загрузка+распаковка). Проверка: `go build ./...`, `go vet ./...`,
  `go test ./...` — зелёные; `go mod tidy && go mod vendor` без лишних зависимостей.

## Этап 1. Примитивы формата (internal/format) — ВЫПОЛНЕН

Инкремент: пакет кодирования и секционного контейнера.
- [x] varint/delta кодеки ([]uint32, []uint64) — encode/decode roundtrip.
- [x] Заголовок: magic "GMRF", version, xxh3-чексумма; каталог секций
  (имя, offset, size); writer (секции дописываются, каталог в конце)
  и reader (проверки magic/version/чексуммы, доступ к секции по имени).
Проверка (выполнена):
- unit-тесты roundtrip varint/delta на краевых случаях (0, 1, max u32/u64,
  монотонные/немонотонные последовательности) — `TestAppendDelta*Roundtrip`;
- unit-тесты writer→reader: несколько секций (в т.ч. пустых, streaming),
  чтение по имени, ошибки при битой чексумме/магии/версии/обрезке;
- `go build ./...`, `go vet ./...`, `go test ./internal/format -race` — зелёные.
Ручная проверка: hexdump тестового файла — magic "GMRF", version=1,
indexOffset=0x1C, каталог из 2 секций, trailer xxh3 — читаемы и корректны.

## Этап 2. Интернирование строк (internal/intern, internal/stringsx) — ВЫПОЛНЕН

Инкремент: арена строк + таблица интернирования без аллокаций на токен.
- [x] `stringsx.Arena`: append байт, границы по uint32-оффсетам, Get(i) []byte.
- [x] `intern.Table`: хеш []byte → id, open addressing, pre-sized, rehash;
  метод Intern(b []byte) (id uint32, existed bool), Get(id) []byte.
Проверка (выполнена):
- unit-тесты Arena/Intern: дубликаты дают один id; уникальные — новые;
  корректность Get после роста таблицы (rehash на 50k вставок при
  ожидании 4); похожие слова дают разные id;
- benchmark Intern на 1M строк: повторные вставки — 63 ns/op,
  **0 allocs/op** (требование FT1 выполнено);
  полная сборка уникального словаря 1M строк — 71 мс, 23 аллокации
  (амортизированный рост арены и rehash);
- `go test ./internal/intern ./internal/stringsx -bench .` — зелёные,
  полный `-race` прогон всех пакетов зелёный.

## Этап 3. Сканер dict.xml (internal/xmlscan)

Инкремент: потоковый байтовый сканер фиксированной схемы.
- [x] Сканер над io.Reader: события OnGrammeme(parent,name), OnLemma(id,text),
      OnForm(text), OnGrammemeRef(v); атрибуты как срезы внутреннего буфера.
- [x] Обработка границ буфера (перенос незавершённых токенов).
Проверка:
- [x] unit-тесты на мини-фикстурах (строки XML): порядок событий, значения атрибутов;
- [x] unit-тест на обрезку буфера (маленький размер буфера = 64 байта);
- [x] интеграционный smoke: первые 10k лемм реального dict.xml парсятся без ошибок
  (`go test -tags integration` или ручной запуск утилиты);
- [x] сравнение числа событий с эталоном: 391 842 леммы / 5 533 109 строк на полном файле.

## Этап 4. Builder и CSR-структуры (internal/build)

Инкремент: программное наполнение словаря (FT8) + структуры памяти.
- [x] Builder: AddGrammeme/AddLemma/AddForm, справочники анкодов, CSR-массивы
  лемм/строк, trie (временный, узлы-структуры) → компиляция в CSR
  (stateOff/transitions/finals), постинг-листы с дедупликацией, exact-hash.
- [x] Метод Build() → иммутабельный снимок (значения, не указатели).
Проверка:
- [x] unit-тесты Builder: маленький словарь (5–10 лемм) вручную; проверка
  lookup по каждому слову, дубликаты форм, одинаковые тексты у разных лемм;
- [x] property-тест: N случайных слов → все найдены; отсутствующие — не найдены;
- [x] `go test ./internal/build -race`.

## Этап 5. Компилятор и загрузчик файла

Инкремент: SaveTo/Open через формат этапа 1 (FT3, FT4).
- [x] Сериализация снимка в секции: delta/varint для оффсетов и постингов.
- [x] mmap-ридер (internal/mmapx): Open(path) → Dictionary-снимок.
Проверка:
- [x] roundtrip-тест: Build → SaveTo → Open → DeepEqual снимков + равенство
  выборок по контрольному набору слов (golden-набор с ожидаемыми грамматиками);
- [x] тест битого файла: усечение, порча чексуммы → осмысленные ошибки;
- [x] замер размера на полном dict.xml: 303 MB (лог в тесте; жёстких ассертов
  нет до стабилизации). Доминанты: texts.data ~67 MB, exact ~47 MB,
  pairs raw ~62 MB — кандидаты на сжатие в FT4-оптимизации (этап 10+).
  Save ~1.0s, Open ~0.3s.

## Этап 7. Интеграция с OpenCorpora end-to-end

Инкремент: полный цикл FT7.
- [x] dictionary.CompileFromXML(path): xmlscan → Builder → снимок
  (+ SaveToAtomic: temp-файл + rename).
- [x] cmd/opencorpora_update: флаги -l (download), -skip-compile, -v;
  компиляция выполняется автоматически после unpack, итог с временем/памятью.
- [x] pkg/opencorpora.Update() снова вызывает компиляцию (loader.Compile()).
Проверка:
- [x] ручной прогон `go run ./cmd/opencorpora_update -l` на реальном dict.xml:
  opencorpora.dict 303 MB создан за 13.7s (scan+build+save), peak heap ~4 GB;
- [x] smoke-тест (pkg/dictionary/smoke_integration_test.go): 50 частотных слов
  резолвятся; контрольные слова («кота»→кот sing,gent; «домами»; омонимы
  «стекла», «пила», «бежал» ≥2 леммы) сверены по фактическим данным словаря.
  Замечание для этапа 8: в dict.xml формы несут только собственные <g>-теги
  (падеж/число); POS и константные теги живут на лемме — при FT2/FT5 выдаче
  полную грамматическую характеристику нужно собирать из леммы + формы.
