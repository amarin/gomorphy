# Требования к библиотеке gomorphy

## Контекст

Библиотека морфологического анализа на основе словаря OpenCorpora (`dict.xml`).
Загрузка и распаковка новых словарей реализованы (`pkg/opencorpora`, не требуют изменений).
Хранение данных проектируется с нуля под перечисленные ниже требования.

Опорные метрики словаря (замерено на `dict.xml`, rev 417257):

| Сущность | Значение |
|---|---|
| Леммы | 391 842 (уникальных текстов: 380 900) |
| Строк словоформ `<f>` | 5 141 267 |
| Всего атрибутированных строк (`l`+`f`) | 5 533 109 |
| Уникальных текстов словоформ | 3 065 312 (~77,6 МБ UTF-8) |
| Уникальных наборов граммем («анкодов») | 876 |
| Уникальных пар (текст, анкод) | 5 393 737 |
| Ссылок / типов ссылок / граммем | 258 650 / 27 / ~120 |

## Функциональные требования

### FT1 — быстрое заполнение памяти из dict.xml
Чтение `dict.xml` с минимальным числом аллокаций. Допускается (и требуется)
замена generic XML-парсера на специализированный сканер фиксированной схемы.
Метрика успеха: сборка полного словаря без роста GC-давления, крупные выделения
памяти только под итоговые структуры (арены/массивы).

### FT2 — быстрая выборка параметров словоформы
Получение грамматических характеристик словоформы за один внутренний запрос,
без аллокаций на запросе. Текущий формат дерева сохраняется по смыслу
(префиксный индекс), проблема связанных атрибутов решается нормализацией:
словарь анкодов (876 наборов) + интернирование текстов.

### FT3 — быстрая запись и чтение скомпилированного словаря
Файл компилированного словаря изоморфен структуре в памяти: загрузка — mmap
(или крупноблочное чтение) + разрезание по секциям каталога, без поэлементного
парсинга. Пообъектная бинарная запись (binutils) не используется.

### FT4 — минимизация размера скомпилированного словаря
Дельта- и varint-кодирование индексов, CSR-упаковка списков, опциональная
компрессия холодных секций. Ориентир: 110–120 МБ без компрессии,
35–45 МБ с zstd (при raw-объёме ~180 МБ).

### FT5 — начальная форма по заданной словоформе
Поиск лемм для словоформы через постинг-листы префиксного индекса;
отдельный индекс не требуется. Не требует большого быстродействия.

### FT6 — нечёткий поиск
Поиск слов в порядке убывания релевантности = возрастания расстояния
Левенштейна до порога k. Реализуется автоматом Левенштейна поверх
CSR-представления префиксного дерева; постоянный дополнительный индекс
не требуется. Не требует большого быстродействия.

### FT7 — библиотечный сценарий обновления словарей
Библиотека предоставляет публичные методы полного цикла обновления словаря
из OpenCorpora: загрузка архива, распаковка, компиляция, запись компилированного
словаря на диск; а также публичные методы загрузки скомпилированного словаря
с диска и получения словоформ (точный поиск, параметры форм, леммы).
Существующий загрузчик/распаковщик (`pkg/opencorpora`) используется как есть.

### FT8 — программное создание и наполнение словарей
Библиотека позволяет создавать новые пустые словари, наполнять их программно
(добавление граммем, лемм, словоформ с наборами граммем через публичный API),
и записывать полученные словари на диск в указанный файл. Формат файла един
для словарей, собранных из `dict.xml` и программно — источник данных не влияет
на сериализацию.

### FT9 — параллельная работа с несколькими словарями
Отсутствие глобальных переменных и синглтонов: всё состояние принадлежит
экземплярам. Допускается одновременная работа с произвольным числом независимых
экземпляров словарей. Чтение загруженного (скомпилированного) словаря
потокобезопасно; операции изменения (builder) синхронизируются либо явно
документируются как непотокобезопасные на уровне экземпляра.

## Влияние требований на реализацию

- **FT1+FT2** → колоночная модель: строковая арена + таблица смещений,
  справочники граммем/анкодов, CSR-списки строк лемм, постинг-листы узлов дерева.
  Никаких пообъектных структур (`map` на узел, указатели на формы) в постоянной памяти.
- **FT2** → нормализация атрибутов: строка словоформы = пара ID `(text_id, ancode_id)`;
  выборка — проход по дереву до узла и срез постинг-листа, O(1) после прохода.
- **FT3+FT4** → секционный формат: `[header][каталог][meta][справочники]
  [арена текстов][offsets][автомат][exact-hash][postings][леммы][links]`;
  varint/delta-кодирование; чтение = mmap + срезание секций.
- **FT5** → следствие основной схемы (lemmaId в постинг-листах, lemmaText у леммы).
- **FT6** → требует навигации по дереву во время исполнения: CSR-trie хранится
  в рантайме целиком (не только exact-hash), обход совместный с DFA Левенштейна.
- **FT7** → разделение ролей: `Builder` (изменяемая фаза сборки) и `Dictionary`
  (иммутабельный рантайм-снимок). Публичный фасад: `Open/Load` с диска,
  `Compile/SaveTo` на диск, lookup-методы. Загрузчик opencorpora остаётся
  отдельным пакетом без зависимости от рантайма словаря.
- **FT8** → Builder принимает данные из двух источников (XML-сканер и программный
  API) через одинаковые внутренние операции (`AddGrammeme/AddLemma/AddForm`),
  сериализация не знает происхождения данных.
- **FT9** → запрет пакетных глобальных состояний; иммутабельность рантайм-снимка
  даёт бесплатную потокобезопасность чтения; конкурентные тесты `-race`
  обязательны; несколько экземпляров = независимые арены и mmap-регионы.
