# Documentation audit after 1.2.0 (release 1.2.1)

## Context

1.2.0 (NER support, see [ner-support.md](ner-support.md)) changed the
public API in many places, and the docs were updated task by task. This
pass reviewed godoc, every user-facing markdown page and the examples
against the code as a whole, and added a page the docs lacked: usage
scenarios — what each feature is *for*.

One code fix rides along: the download loaders panicked in any program
that had not called `logging.Init`.

## What changed

**Loader panic (code).** `pymorphy.NewLoader`, `opencorpora.NewLoader` and
`unimorph.NewLoader` called `logging.NewNamedLogger`, which panics until
`logging.Init` runs («logging: set backend first»). The CLI calls `Init` in
every command, and each loader package's tests call it in `TestMain` — so
neither caught it; any library caller crashed. `amarin/logging` has no way
to ask whether `Init` ran, so `common.NewLoaderLogger` recovers that panic
and returns a discarding logger. Tests in `pkg/common` (a package that never
calls `Init`) cover all three loaders.

**Usage scenarios.** [scenarios.md](../scenarios.md) and its Russian twin:
15 scenarios (analysis, lemmas, known word vs. guess, dictionary NER,
thematic TSV dictionaries, merge, several dictionaries, typos, е/ё policy,
other languages, embedding/Windows, content-hash caching, tag comparison,
manual inspection, fetching sources). Each names the calls, links a
runnable example, states "available since" and a per-feature **History**
drawn from CHANGELOG, which stays the source of truth.

**Examples.** New `examples/{ner,typos,embed,contenthash,tagmap}`; `embed`
commits a 2.8 KB `names.dat` (regenerated by `go run ./examples/embed/gen`)
so it shows a real `//go:embed` + `OpenBytes`. Every example that needs no
external data ends with an `// Output:` block, and `go test ./examples/`
runs each one and compares — the examples can no longer rot silently. New
`ExampleXxx`: `Dictionary_Parse` (Predicted), `NewCharPolicy`,
`NoCharPolicy`, `Dictionary_ContentHash`, `MultiDictionary_IsKnown`,
`tagmap.Map`, `tagmap.Known`.

**godoc.** The package overview now covers Predicted/IsKnown, CharPolicy,
OpenBytes and the lifecycle. Doc comments that contradicted the code:
`Info` (never nil for built/imported dictionaries), `TagSetName` (Builder
and ImportTSV report "builder"/"tsv", not ""), `ContentHash` (not safe
after `Close`), `FuzzyTop` with `maxWords ≤ 0` (returns CharPolicy variants
too), `AddForm` (does not trim), `ImportTSV` (trims tags; empty input is an
empty dictionary, not an error), opencorpora `Progress` (fires during the
DAWG build by key count, not every 10 s). Two stray comments leaked into
package docs (`multidict.go`, pymorphy2 `recompile.go`).

**Markdown.** README (sources, Windows/OpenBytes, features, sizes),
`library.md` and `cli.md` (real CLI output samples, `fuzzy`/`top` label
column, `--lang`, lower-casing), `installation.md` (pymorphy as the default
source), `glossary.md` (CharPolicy was described as two-way and empty by
default; pre-1.0 structures labelled legacy), `implementation.md`,
`requirements.md` (marked historical), `mcp.md`, `comparison.md`. The
Russian `library.md` claimed that dense dictionaries could not be saved
and had no fuzzy search, and gave the old е/ё distance; it is now a full
mirror of the English page, as are `cli.md` and `installation.md`.

## Open issues (not fixed in 1.2.1)

Found by the audit, need code changes, and are left for a decision:

- `Sync` never refreshes an existing unpacked copy: after a new download
  the old `dict.xml` / `data/` stays (opencorpora, pymorphy).
- `DownloadUpdate`/`UnpackUpdate` create `./.data/<domain>` via
  `common.MakeDomainDataPath`, ignoring a custom `dataPath` (opencorpora,
  pymorphy; unimorph already avoids it).
- opencorpora `DownloadUpdate` does not check the HTTP status and would
  save an error page as the archive.
- `Sync(skipDownload=true)` still makes a network request
  (`IsUpdateRequired` runs first).
- Downloads are not atomic: a failed download leaves a truncated file.
- `Dictionary.Language`, `Fuzzy`, `FuzzyTop` panic on a nil receiver while
  `Parse`, `Lemma`, `Info`, `TagSetName` return zero values.
- `ImportTSV` of an empty stream returns an empty dictionary, while
  `Builder.Build` with no entries returns `ErrNoEntries`.
- `ErrIncompatibleDictionaries` lacks the `morphology:` prefix the other
  sentinel errors use.

## Testing

`make lint`, `make test` (race), `go test ./examples/`, and the integration
suite (`-tags integration`, real dictionaries under `.data/`).
