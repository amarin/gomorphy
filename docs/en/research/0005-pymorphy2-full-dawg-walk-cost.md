# Стоимость полного обхода pymorphy2 `words.dawg` для рекомпиляции под плотный алфавит

**Дата:** 2026-09-16
**Статус:** гипотеза подтверждена
**Проверял(а):** Aleksey Marin (сессия с Claude Code)
**Связанные документы:** [0004-dawg-dense-alphabet-with-payload.md](0004-dawg-dense-alphabet-with-payload.md), раздел «Плотный алфавит в проде: тезисы обсуждения (пауза, не решено)» в [../todo.md](../todo.md)

## Контекст

При обсуждении продакшн-внедрения плотного 1-байтового DAWG-алфавита
(2026-09-15/16) один из двух вариантов — «выпилить прямую поддержку
сырого pymorphy2 `words.dawg` и пересобирать pymorphy2-словари через тот
же конвейер, что и OpenCorpora» — был отклонён от немедленной реализации
с формулировкой: «это реально новый объёмный кусок работы (полноценный
«pymorphy2→gomorphy-native рекомпилятор»), больше по объёму, чем сама
адаптация read-path под 2 формы». Решение о пути не принято именно из-за
этой оценки трудоёмкости.

Ключевой шаг такого рекомпилятора — прочитать **весь** словарь pymorphy2
(каждую пару «словоформа → (paradigm_id, form_id)» из `words.dawg`), чтобы
прогнать текст каждой словоформы через `DenseAlphabet.Encode` и пересобрать
DAWG. До этой сессии в кодовой базе не было ни одного места, которое
обходило бы `words.dawg` целиком — только точечные запросы через
`SimilarItems` (`pkg/morphology/parse.go:87`) на конкретное слово.

Текущий импорт pymorphy2 (`pkg/morphology/importers/pymorphy2/import.go:59-69`)
читает `Paradigms`/`Suffixes`/`Prefixes` готовыми из
`paradigms.array`/`suffixes.json`/`paradigm-prefixes.json` — эти таблицы
не вычисляются из текста слов (в отличие от OpenCorpora-импорта, где
`Suffixes`/`Prefixes` строятся через LCP из тех же переменных, что и
DAWG-ключ, `pkg/morphology/importers/opencorpora/import.go:150-234`).
В `words.dawg` ключ — буквально текст словоформы, payload — 4 байта
big-endian (`para uint16`, `form uint16`), см.
`pkg/morphology/parse.go:199-206` (`Dictionary.reading`).

В `pkg/morphology/internal/dawg.go` уже существует приватный тип
`completer` (`start`/`next`, dawg.go:290-354) — обходчик под-автомата по
`guide`. Он используется в уже экспортированном `DAWG.ValuesForIndex`
(dawg.go:231-239) и косвенно подтверждён тестом
`TestDebugStress` (`zz_debug_stress_test.go`), который строит DAWG из 33
ключей (11 слов × 3 варианта payload) и обходит **всё** дерево от корня
(`c.start(0, "")` + цикл `c.next()`), логируя число найденных ключей.
Также уже существуют `DAWG.ForEachChild` (dawg.go:245-258, обход исходящих
рёбер узла по guide) — то есть все примитивы, нужные для полного обхода,
уже в проде и уже покрыты тестами по отдельности, просто не собраны в одну
функцию полного обхода.

## Гипотеза

Если написать обход всего `words.dawg` (перечисление всех пар
«словоформа → payload») поверх уже существующих экспортированных методов
`DAWG.ForEachChild` и `DAWG.ValuesForIndex`, то это будет на порядки
дешевле, чем оценка «объёмный новый кусок работы» из обсуждения
2026-09-15/16 — потому что (а) сам механизм обхода уже реализован и
протестирован, обёртка над ним тривиальна (~15-20 строк), и (б) для
pymorphy2 не нужно пересчитывать `Paradigms`/`Suffixes`/`Prefixes` (как
пришлось бы для OpenCorpora), поскольку DAWG-ключ — это независимая от
этих таблиц сущность (сам текст словоформы). Следствие: полный обход
реального pymorphy2-словаря (~3M словоформ) должен завершаться за секунды,
а не минуты/часы, и не требовать новой инфраструктуры вроде хранения всего
словаря в памяти сверх уже читаемых структур.

## Эксперимент

**Данные:**
- Реальный словарь pymorphy2-dicts-ru, версия `2.4.417127.4579844`, wheel
  `pymorphy2_dicts_ru-2.4.417127.4579844-py2.py3-none-any.whl`
  (8 212 425 байт), скачан с PyPI
  (`https://files.pythonhosted.org/packages/3a/79/.../pymorphy2_dicts_ru-2.4.417127.4579844-py2.py3-none-any.whl`)
  и распакован через новый `pkg/pymorphy.Loader` (см. ниже) в
  `.data/pymorphy/data/`. Файл `words.dawg` — 7 360 520 байт.
- Дополнительно (для отдельного синтетического захода, см. «Отклонение
  от плана» ниже): список словоформ OpenCorpora, 3 065 312 строк,
  извлечён командой
  `grep -o '<f t="[^"]*"' .data/opencorpora/dict.xml | sed -E 's/<f t="//;s/"$//' | sort -u`
  (эта же команда описана в док-комментарии
  `pkg/morphology/internal/alphabet_compare_integration_test.go`).

**Инструменты:** throwaway-тест внутри пакета
`pkg/morphology/internal` (доступ нужен только к уже экспортированным
`ReadDAWG`, `DAWG.ForEachChild`, `DAWG.ValuesForIndex`, `PayloadSeparator`
— то есть тот же обход воспроизводим и из пакета-импортёра
`pkg/morphology/importers/pymorphy2`, без доступа к неэкспортированным
деталям). Тест не оставлен в дереве (только в этом эксперименте).

**Метод измерения:** рекурсивный обход от корня (`index=0`):
`ForEachChild` на каждом узле; ребро с меткой `PayloadSeparator` — конец
словоформы, `ValuesForIndex` на узле-получателе даёт все payload-значения
этого ключа; иначе — рекурсия глубже с добавлением байта-метки к
накопленному префиксу. Каждый payload декодировался как `(para, form)`
двумя big-endian `uint16`, как это делает `Dictionary.reading`.
Засекалось время всего обхода (`time.Since`), считалось число найденных
ключей и максимальные увиденные `para`/`form`, как грубая проверка
согласованности с `paradigms.array`.

**Шаги воспроизведения:**
```bash
# Получение реального словаря (шаги download+unpack; см. pkg/pymorphy):
go run <временная программа, вызывающая pymorphy.NewLoader("").Sync(false)>
# → .data/pymorphy/data/words.dawg (7 360 520 байт)

# Обход words.dawg (throwaway-тест в pkg/morphology/internal, использующий
# только ReadDAWG/ForEachChild/ValuesForIndex/PayloadSeparator):
GOMORPHY_WALK_SPIKE_DAWG="$(pwd)/.data/pymorphy/data/words.dawg" \
  go test -tags=integration ./pkg/morphology/internal/ \
  -run TestScratchWalkRealPymorphy2 -v -timeout 120s
```

**Отклонение от плана (честная фиксация методологической ошибки):**
первый заход измерял не то, что нужно — синтетический тест строил DAWG
«с нуля» из 3 065 312 ключей OpenCorpora со случайным `uint32`-payload
через `BuildDAWG`, чтобы затем обойти получившееся дерево. Сборка не
уложилась в 10-минутный таймаут (упёрлась в глубокую рекурсию
`placer.place`, `dawgbuild.go:316` — известное свойство алгоритма
размещения при большом N, не связанное с вопросом обхода). Это измеряло
стоимость **построения** DAWG с нуля, а не стоимость **обхода** уже
готового файла — а именно обход и есть операция, нужная рекомпилятору
(он читает уже собранный pymorphy2 `words.dawg`, а не строит новый с
нуля). Заход отброшен, вместо него — прямой обход реального
`words.dawg` без какой-либо пересборки (см. выше).

## Результаты

| Вариант | Ключей | Время обхода | Метод |
|---|---|---|---|
| синтетика, `TestDebugStress` (существовавший тест) | 33 (11 слов × 3 payload) | не измерялось отдельно, `completer` нашёл 33/33 | `completer.start(0,"")`+`next()` |
| **реальный pymorphy2 `words.dawg`** | **3 064 708** | **570.6 мс** | `ForEachChild`+`ValuesForIndex` (обёртка ~35 строк) |

Дополнительные проверки согласованности на реальных данных:
- `payloads shorter than 4 bytes = 0` — ни один payload не оказался
  повреждён/усечён при декодировании как `(para,form)`.
- `max para id seen = 3455` — согласуется с ожиданием «полный словарь:
  ~3000 парадигм» из `TestFullDictStructure`
  (`pkg/morphology/importers/pymorphy2/full_dict_integration_test.go:30`)
  и с размером `paradigms.array` (857 102 байта).
- `max form id seen = 232` — правдоподобная верхняя граница числа форм в
  одной парадигме.
- Отдельно (уже существующим импортёром, без изменений) на этом же
  скачанном словаре: `TestFullDictStructure`/`TestFullDictVseReadings`
  прошли зелёными, `Parse("все")` дал 2 найденных ключа / 5 разборов —
  подтверждение, что `.data/pymorphy/data/` пригоден для реального
  дальнейшего использования, не только для этого спайка.

Для сравнения по масштабу: словник OpenCorpora на этой же машине —
3 065 312 уникальных словоформ (в пределах 0.02% от числа ключей
pymorphy2 `words.dawg`) — оба словаря одного порядка, найденные цифры не
являются игрушечным нерепрезентативным случаем.

## Выводы

Гипотеза подтвердилась: полный обход реального pymorphy2 `words.dawg`
(~3.06M пар «словоформа → (para,form)») занимает **570 мс**, используя
только уже существующий и по отдельности протестированный код
(`ForEachChild`, `ValuesForIndex`), без построения чего-либо с нуля и без
доступа к неэкспортированным деталям пакета `internal`. Это на порядки
дешевле, чем подразумевала формулировка «объёмный новый кусок работы» из
паузы 2026-09-15/16 — по крайней мере для шага «прочитать весь словарь»,
который и был источником этой оценки.

Что это меняет в оценке трудоёмкости рекомпилятора pymorphy2→gomorphy-native
для `words.dawg` конкретно:
1. Обход — не риск и не отдельная задача, а ~30-40 строк, переиспользующих
   существующий API.
2. `Paradigms`/`Suffixes`/`Prefixes` не пересчитываются (в отличие от
   OpenCorpora-пути) — значит нет риска класса «синхронизация DAWG-ключа
   и таблиц суффиксов/префиксов», который дважды уже ловился в проекте
   (`paradigmKeyHash`, см. roadmap-память проекта).
3. Оставшаяся, не измеренная этим экспериментом работа: (а) прогнать
   каждую найденную словоформу через `DenseAlphabet.Encode`, (б)
   пересобрать `BuildDAWGWithValues` с тем же payload, (в) сериализовать
   таблицу алфавита в `.dat`, (г) round-trip регрессия — сравнить
   `Parse()` до/после на выборке слов. Сама пересборка (`BuildDAWG`) на
   3M ключей уже отдельно задокументирована харнессом
   (`alphabet_compare_integration_test.go`) как «занимает минуты» — это
   не обходной вопрос, но и не открытие этой сессии.
4. Вопрос про `prediction-suffixes-N.dawg` (3 095 048 + 32 264 + 1 544
   байта) и `p_t_given_w.intdawg` (2 884 616 байт) остаётся открытым:
   тот же обходчик к ним применим технически (это тоже `DAWG`), но их
   ключи — не то же самое, что текст словоформы (суффиксы слов и
   `"слово:тег"` соответственно) — решение, распространять ли на них
   плотный алфавит, требует отдельного рассмотрения, не покрытого этим
   экспериментом.

**Границы применимости:** измерено на одной машине, один прогон, без
профилирования аллокаций/GC. Число потенциально не устойчиво при иной
архитектуре/загрузке машины, но порядок величины (сотни миллисекунд,
не минуты) достаточно однозначен, чтобы снять сам довод «это дорого» из
рассмотрения при принятии решения о пути pymorphy2.

Данные для тестирования получены новым кодом (`pkg/pymorphy.Loader`,
шаги download+unpack по плану из «Этап 21» в `todo.md`), который остаётся
в дереве и не является частью эксперимента — сам эксперимент использовал
только уже существующие внутренние примитивы `DAWG`.
