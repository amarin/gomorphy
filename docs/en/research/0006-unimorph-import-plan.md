## Контекст

Задача — проанализировать черновик этапа 16 (импорт словаря UniMorph из
TSV) и составить короткий план реализации, перечислив неясные вопросы для
дополнительного обсуждения и оценив объём работ. Черновик
`stage-16-import-unimorph.md` ссылается на Builder API (`AddLemma`/
`AddForm`), `Options.Mapping`, публичные `CompileFromUniMorph*` — часть из
этого в текущей кодовой базе уже не существует; анализ ниже сверяет
черновик с фактическим кодом и фиксирует, что в плане этапа нужно
переписать, что уточнить и сколько это стоит.

Данные-ориентир: `unimorph/rus` — 473 482 строки, 28 069 лемм, 353 004
уникальных словоформ, licence CC-BY-SA 3.0 (полная таблица — в
[unimorph.md](../unimorph.md) §4).

## Актуальный срез кода (проверено чтением 2026-09-16)

Что реализовано в репозитории сейчас и на что опирается импортёр:

1. **Builder API (`AddLemma`/`AddForm`) НЕ существует** — ни в
   `pkg/morphology`, ни в `internal` (grep по коду пуст). Эталонный
   импортёр OpenCorpora строит словарь напрямую:
   `lemmaEntry` → LCP-стем форм → (suffix_id, tag_id) → дедуп парадигм →
   DAWG с payload, с шардированием по лимиту суффиксов
   (`importers/opencorpora/import.go:112-291`, `shard.go`). Черновик
   этапа 16 описывает **старую** архитектуру (этапы 4–10, `pkg/dictionary`
   + Builder); с этим же связано устаревшее упоминание `pkg/dictionary` в
   `unimorph.md` §5.1.

2. **«Лемма» в текущей модели — это форма 0 парадигмы.** `readingForm`
   (`pkg/morphology/parse.go:201-226`): для `form==0` норма = само слово,
   для `form!=0` — `prefix₀ + stem + suffix₀`; `LemmaRef.Normal` и
   `LemmaRef.Tag` берутся из формы 0 (`lemma.go:15-36`). Значит
   «AddLemma(лемма, base-граммемы)» из черновика отображается не
   отдельной сущностью, а обязательной формой 0 с тегом формы `== лемма`.

3. **Теги — opaque-строки.** TagSet интернирует произвольные имена
   (`internal/tagset.go:23-37`, лимит 65 536). Bundle UniMorph можно
   сохранять как есть (например, `N;ACC;SG`) — CLI-ожидание черновика
   (`lookup кота → N;ACC;SG`) достигается без какого-либо маппинга.

4. **Язык и CharPolicy зашиты в импортёре.** OpenCorpora жёстко ставит
   `language="ru"` и `internal.RussianCharPolicy()`
   (`import.go:276-284`). У UniMorph-импортёра фиксированного языка нет —
   нужен явный параметр (см. Q1).

5. **Шардирование** (`shard.go`, лимит 65 536 суффиксов на шард)
   переиспользуемо; для `rus` (353K форм) почти наверняка достаточно
   одного шарда, но механизм стоит сохранить для других языков.

6. **Данных/загрузчика UniMorph в репо нет.** Для OpenCorpora и pymorphy2
   есть loader'ы (`pkg/opencorpora`, `pkg/pymorphy`) и данные в `.data/`;
   для UniMorph — ни того, ни другого (см. Q4).

## Расхождения черновика с фактической архитектурой

1. Пункт «Pipeline. Лемма/Формы» (`AddLemma`/`AddForm`) устарел — переписать
   в терминах «лемма = форма 0, формы = остальные строки», без Builder.
2. Публичный API: в черновике `CompileFromUniMorph(r io.Reader)` без опций,
   а `ImportFromTSV(r, opts Options)` — с опциями; языковой код нигде не
   передаётся. Нужно согласовать сигнатуры (см. Q1).
3. `docs/unimorph.md` §5.1/5.2: ссылки на `pkg/dictionary` и старый
   `pkg/unimorph` — устарели; фактическое место — `pkg/morphology/importers/unimorph/`.
4. Интеграционные тесты черновика требуют реальный `rus`-файл, источника
   которого в проекте нет (Q4).

## Предлагаемые дизайн-решения для импортёра

1. **Формат строк (Streaming).** `bufio.Scanner` с увеличенным буфером
   (~1 МБ — составные/дефисные токены, как в черновике), split по `\n` с
   отрезанием `\r`. Строка — ровно 3 поля через `\t`. Сортировка строк по
   лемме не гарантирована контрактом — нужена аккумуляция:
   `map[лемма] → lemmaEntry` (28K записей для `rus` — дёшево), порядок
   форм внутри леммы = порядок строк.

2. **Лемма = форма 0 (ключевое решение).**
   - Есть строка с `form == лемма` → её bundle становится тегом формы 0
     (если таких строк несколько с разными bundles — берутся все: первая
     как форма 0, остальные как обычные формы-омонимы — нативный
     синкретизм формы леммы, корректно обрабатывается существующими
     механизмами).
   - Нет строки с `form == лемма` → синтезировать форму 0 с текстом леммы
     и пустым тегом (`""` допустим в TagSet). Это необходимо, т.к. иначе
     `Lemma()` для форм леммы вернул бы не лемму, а произвольную форму
     (`parse.go:211-215`), и `Parse(лемма)` не сработал бы.
   - **Текст леммы всегда включается во вход `lcp()`** (технически — в
     множество форм для вычисления стема). Иначе для супплетивных групп
     («я» vs «меня», «человек» vs «люди») стем не обязательно префикс
     леммы, и реконструкция нормы сломается. При LCP по формам+лемма стем
     всегда префикс леммы → суффикс формы 0 всегда валиден.
   - Пустая лемма → лемма := словоформа (согласовано в черновике;
     в этой модели тривиально: форма 0 = словоформа, её же тег).

3. **Opaque-теги.** Тег = bundle вербatim (без переупорядочивания,
   `strings.Split(bundle, ";")` нужен только если захотим отдельные
   граммемы; для TagSet достаточно строки `N;ACC;SG` as-is). Порядок
   признаков сохраняется, LGSPEC-признаки не трактуются. Маппинг
   `Options.Mapping` (FT12/bundl-проекция) — см. Q2.

4. **Дедуп и синкретизм.** Точные дубликаты строк в `rus` отсутствуют;
   повтор `(форма, bundle)` в пределах леммы схлопывается дедупом парадигм
   (`paradigmKeyHash`) и `dedupEntries`; одинаковый текст с разными
   bundles — разные `(key, val)` в DAWG (не дубликат) — чтения сохраняются
   (регрессия-прецедент — `TestImportFromXMLHomonymFormsBothSurvive`).

5. **Многословные/дефисные токены.** Библиотека байто-ориентирована, LCP —
   руно-безопасный (`lcp` в `importers/opencorpora/import.go:402-428`);
   дополнительных ограничений нет.

6. **Шардирование и Progress.** Переиспользовать модель `FillOnDemand`
   (копию/вынесение общей части — см. Q3). Progress-callback — опционально
   (сборка 473K строк — секунды; для паритета сигнатуры можно сохранить).

## Принятые решения (Q&A 2026-09-16)

Ответы пользователя на открытые вопросы, зафиксированы как решения. Там,
где ответ отклонил рекомендацию, помечено «↷ отклоняет рекомендацию».

**Q1. Языковой код и CharPolicy — принято (↷ частично отклоняет рекомендацию).**
На первом этапе всегда загружается **только русский язык**; ссылки загрузки
словаря — **статические**; для языка — отдельный конструктор. Код строится
«с заделом» на поддержку загрузки и импорта других языков (в очень далёкой
перспективе). Следствия:
- `Options.Language` — обязательное поле импортёра; перспективе поддерживается
  `ru` (на первом этапе — только `ru`), для других языков ошибка.
- CharPolicy выбирается по языку: `ru` → `internal.RussianCharPolicy()`,
  иначе `nil`.
- CLI: флаг `-lang` (default `ru`) + конструктор языка в загрузчике.
- Загрузчик принимает язык в конструкторе (`NewLoader(language, dataPath)`),
  URL формируется по языку, но фактически разрешено только `ru`.

**Q2. Маппинг тегов UniMorph → OpenCorpora — отложить (принята рекомендация).**
`Options.Mapping` в скоуп этапа 16 **не входит**. Теги — opaque-строки bundle
вербатим (`N;ACC;SG`). Маппинг — отдельный инкремент (+0.5–1.5 дня), если
понадобится.

**Q3. Общий TSV-движок — на этапе 16 минимум (принята рекомендация).**
Отдельный минимальный импортёр UniMorph сейчас; вынос общего
параметризуемого движка — при реализации этапа 19. Копия общих кусков
(`lcp`, `paradigmKeyHash`, `FillOnDemand`) допустима, отмечена комментарием
как кандидат на вынос.

**Q4. Источник данных для интеграционных тестов — добавить загрузчик (↷ отклоняет рекомендацию).**
Загрузчик UniMorph по образцу `pkg/pymorphy` (а не ручная загрузка):
`pkg/unimorph` с `DomainName="unimorph"`, статический URL
`https://raw.githubusercontent.com/unimorph/<lang>/master/<lang>`, загрузка
в `.data/unimorph/<lang>` (+0.5 дня к оценке этапа 5).

**Q5. Битые строки — выводить ошибку, но не падать (принята рекомендация).**
Строка ≠ 3 `\t`-поля → ошибка с номером строки **выводится** (логируется),
импорт **продолжается** с следующей строки (не aborts). Пустой bundle —
допустимый случай (тег `""` в TagSet).

**Q6. «Лемма всегда форма 0» — подтверждено (принята рекомендация).**
Синтезировать форму 0 с текстом леммы и пустым тегом `""`, если нет строки
`form == лемма`; текст леммы всегда включается во вход `lcp()`. Для `rus` это
добавляет до ~28K ключей в DAWG.

**Q7. Progress/BuildInfo — принята рекомендация.**
`BuildInfo.Source="unimorph"`; `SourceVersion` — из опции (статический URL /
дата загрузки); Progress-callback — опционально (nil достаточно).

## Границы применимости

Числа объёма — экспертная оценка по аналогии с этапом 15 (OpenCorpora),
не измерение. Не затронуты (сознательно вне скоупа): маппинг тегов (отложен
Q2), лексикографическая сортировка тегов, нагрузка на `TagSet` (28K лемм ×
небольшое число уникальных bundles — далеко от лимита 65 536). Оценка
шардинга для `rus` (1 шард) — по объёму немерена; механизм переиспользуется
для страховки.
