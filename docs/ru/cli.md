# CLI: gomorphy

Утилита морфологического анализа слов на основе скомпилированного словаря
GMOR (`.dat`, единый формат для источников pymorphy2/OpenCorpora/UniMorph
— см. [library.md](library.md)), а также утилита получения и сборки
исходных словарей.

## Общая форма вызова

```bash
gomorphy <command> [flags] [args]
gomorphy cli [flags]        # интерактивная консоль
```

### Глобальные флаги (общие для всех команд поиска)

| Флаг | Описание |
|------|----------|
| `-d, --dictionary <path>` | путь к `.dat`-файлу или каталогу с `.dat`-файлами (можно указывать несколько раз — словари объединяются в один индекс с сохранением порядка) |
| `-v, --verbose` | подробное логирование |
| `-l, --log <path>` | писать лог в файл вместо stderr |

Если `-d/--dictionary` не задан, используется путь из переменной окружения
`GOMORPHY_DICTIONARY`.

## Команды поиска

### `lookup` — точный поиск словоформы

Возвращает все грамматические разборы заданного слова.

```bash
gomorphy lookup -d opencorpora.dat кота
```

Вывод (по одной строке на разбор, поля через TAB):

```
кота	кот	sing,nomn	para#0/33/1	opencorpora/0.92/417127
```

Формат: `<слово>\t<лемма>\t<тег>\tpara#<dict>/<shard>/<para>\t<словарь>` — компонент
`dict` указывает, из какого по счёту (начиная с 0) объединённого словаря
пришёл разбор, если указано несколько `-d`; `<словарь>` — его имя и версия.
Разбор, угаданный по окончанию (слова нет в словаре), заканчивается ещё
одной колонкой `(predicted)`. Эта колонка — необязательное 6-е поле:
строка со словарным разбором содержит 5 полей через TAB, строка с
предсказанным — 6; число колонок меняется от строки к строке, а не
фиксировано для всего вывода.

### `lemmas` — поиск начальных форм

Находит начальную форму (лемму) для заданного слова.

```bash
gomorphy lemmas -d opencorpora.dat кота
```

Вывод: `<лемма>\t<тег начальной формы>` — по одной строке на омоним
(разные части речи/значения одного текста).

### `fuzzy` — нечёткий поиск

Слова словаря в пределах расстояния Левенштейна `maxDist` (по умолчанию 2).

```bash
gomorphy fuzzy -d opencorpora.dat кот 1
```

Вывод (отсортирован по расстоянию, затем по слову):

```
0	кот	dict#0
1	бот	dict#0
1	вот	dict#0
1	гот	dict#0
...
```

Формат: `<расстояние>\t<слово>\tdict#<dict>`.

### `top` — N ближайших слов

Как `fuzzy`, но расстояние расширяется итеративно, пока не набрано `N` слов.

```bash
gomorphy top -d opencorpora.dat кот 5
```

```
0	кот	dict#0
1	бот	dict#0
1	вот	dict#0
1	гот	dict#0
1	дот	dict#0
```

### `cli` — интерактивная консоль

```bash
gomorphy cli -d opencorpora.dat
```

```
gomorphy> lookup кота
кота	кот	sing,nomn	para#0/33/1
gomorphy> exit
```

TAB — автодополнение команд (`lookup`, `lemmas`, `fuzzy`, `top`, `exit`,
`quit`), `exit`/`quit` — выход.

## Получение и сборка словарей

### `download` — скачать исходный архив

```bash
gomorphy download opencorpora
gomorphy download pymorphy
```

### `unpack` — распаковать уже скачанный архив

```bash
gomorphy unpack opencorpora
gomorphy unpack pymorphy
```

### `build` — скомпилировать источник в `.dat`

По умолчанию берёт уже распакованный источник; `-i/--input` позволяет
указать путь явно (например, чтобы скомпилировать `dict.xml` напрямую,
без сети).

```bash
gomorphy build opencorpora -i dict.xml -o out.dat
gomorphy build pymorphy -i /path/to/unpacked/dir -o out.dat
```

Флаги:

| Флаг | Описание |
|------|----------|
| `-i, --input <path>` | скомпилировать этот путь напрямую, минуя загрузчик |
| `-o, --output <path>` | путь выходного `.dat`-файла (по умолчанию `.data/<type>/<type>.dat`) |

### `update` — download + unpack + build одной командой

```bash
gomorphy update opencorpora
gomorphy update pymorphy -o /tmp/pymorphy.dat
```

Флаги: `-o, --output <path>` — как у `build`.

### `import` — сборка `.dat` из TSV словоформ

```bash
gomorphy import tsv words.tsv -o out.dat
gomorphy import tsv words.tsv -o out.dat --source ships
```

Читает поток словоформ с разделителем TAB и собирает `.dat` (плотный
1-байтовый алфавит, prediction пересобран, как и у других
самостоятельно собранных словарей). Используется для тематических
словарей без внешних источников (без интернета, без базового словаря
OpenCorpora): подготовьте TSV, импортируйте его в `.dat`.

Формат, одна запись на строку:

```
lemma<TAB>wordform[<TAB>tags]
```

- Пустые строки и строки, у которых первый непробельный байт — `#`,
  пропускаются.
- Отсутствующая лемма делает словоформу леммой самой себе (auto-lemma).
- Начальные/конечные пробелы обрезаются в каждом поле (разделитель —
  только TAB).
- Теги — непрозрачные произвольные строки, регистрируются
  автоматически как граммемы — без привязки к набору OpenCorpora.

Всё остальное — строка с 1 столбцом или более чем с 3 — ошибка с
указанием номера строки.

`-o` обязателен (у импортёра нет пути по умолчанию).

Флаги:

| Флаг | Описание |
|------|----------|
| `-o, --output <path>` | путь выходного `.dat`-файла (обязателен) |
| `--source <name>` | значение для `BuildInfo.Source` (по умолчанию `tsv`) |

### `merge` — объединение словарей

```bash
gomorphy merge --mode add -o merged.dat base.dat overlay.dat
gomorphy merge --mode replace -o merged.dat base.dat overlay1.dat overlay2.dat
```

Читает базовый словарь плюс один или несколько overlay (скомпилированные
`.dat`-файлы) и записывает объединённый `.dat`, не трогая входные
файлы. Слияние структурное: база сохраняет свои парадигмы, имя набора
тегов (`TagSet.Name`, так что нормализация тегов продолжает работать),
вероятности и prediction для слов вне словаря; слова overlay
добавляются в эту структуру. Слияние небольшого overlay с
`pymorphy.dat` занимает ~25 с (доминирует пересборка индекса слов) и
увеличивает размер файла только на размер overlay. Ожидайте расход
памяти того же порядка, что и при сборке базового словаря из
исходников — около 4.6 ГБ пикового RSS для полных русских словарей
pymorphy2/OpenCorpora (сборка самого `pymorphy.dat` достигает пика
около 3.5 ГБ).

- `--mode add` — слова overlay, которые уже есть в базе (или в более
  раннем overlay), пропускаются; новые слова добавляются.
- `--mode replace` — разборы слова из overlay заменяют существующие
  разборы этого слова; при нескольких overlay побеждает последний.
- `--rebuild-prediction` — пересобрать prediction из всех
  объединённых слов (полезно при слиянии тематических словарей друг с
  другом); по умолчанию сохраняется prediction базы, и слова overlay
  в него не попадают.

Входные словари должны совпадать по языку в точности (словарь с
пустым языком отклоняется против базы `"ru"`); два разных известных
словаря тегов (например, `opencorpora-int` и `unimorph`) также
отклоняются.

Выходной `BuildInfo.Source` — `merge`; язык базы, `SourceVersion` и
`Description` переносятся без изменений.

`-o` обязателен и не может совпадать ни с одним входным путём —
merge не должен незаметно перезаписать один из своих источников.

Флаги:

| Флаг | Описание |
|------|----------|
| `-o, --output <path>` | путь выходного `.dat`-файла (обязателен) |
| `--mode <add\|replace>` | политика слияния (обязателен, регистронезависим) |
| `--rebuild-prediction` | пересобрать prediction из всех объединённых слов (только для однородного результата с одним шардом) |

### `split` — пока не реализована

Команда-заглушка для будущего разбиения `.dat`-словарей; сейчас
завершается ошибкой `not yet implemented`.

### `version`

```bash
gomorphy version
```

Печатает версию библиотеки.
